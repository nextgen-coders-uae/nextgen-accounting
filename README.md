# نكست جين للمحاسبة — NextGen Accounting

منتج من **نكست جين كودرز — NextGenCoders** · [nextgen-coders.dev](https://nextgen-coders.dev)
شركة مرخّصة — رخصة رقم 55507، المنطقة الحرة بعجمان، الإمارات.

نظام محاسبة عربي بالقيد المزدوج للمكاتب المحاسبية والإدارات المالية ومكاتب إدارة الميزانية.
يعمل على جهاز العميل بدون إنترنت، ويفتحه باقي موظفي المكتب من المتصفح عبر الشبكة المحلية.

## المميزات
- دليل حسابات + شجرة حسابات
- دفتر قيود اليومية (مسودة / ترحيل / تسوية / افتتاحي / إقفال) مع حماية من تكرار القيود
- الأستاذ العام + ميزان المراجعة
- قائمة الدخل + المركز المالي + التدفقات النقدية
- موازنة تقديرية ومقارنتها بالمصروف الفعلي
- مناطق / فروع منفصلة
- صلاحيات: مدير / محاسب / مشاهدة فقط + سجل عمليات
- تصدير Excel رسمي بخانات توقيع قابلة للتعديل، واستيراد من قوالب Excel
- نسخ احتياطي شهري تلقائي + استعادة من ملف
- «نسيت كلمة المرور؟» عبر سؤال الأمان
- قاعدة بيانات SQLite — لا تحتاج تسطيب
- **واجهة ثنائية اللغة (عربي / English)** بزر واحد، مع حفظ لغة كل مستخدم، وتقارير Excel بلغة الواجهة
- وضع داكن وفاتح + أيقونات موحّدة (Lucide) + خطوط مضمّنة (Tajawal / Inter) تعمل بدون إنترنت

## التشغيل للتطوير
```bash
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt pyinstaller
.venv\Scripts\python app.py
```
ثم افتح `http://localhost:5000`

دخول أول مرة: `admin / admin123` (مدير) — `accountant / accountant123` (محاسب) — `viewer / viewer123` (مشاهدة)

## الاختبارات
شغّل النظام ثم:
```bash
.venv\Scripts\python -m pip install requests
.venv\Scripts\python test_system.py
```
(على قاعدة بيانات جديدة — احذف أو انقل مجلد `instance` قبلها)

## الترجمة
- النص العربي نفسه هو مفتاح الترجمة: `{{ _("...") }}` في القوالب، و`T("...")` في الجافاسكربت، و`_("...")` في بايثون.
- القاموس الإنجليزي في `translations/en.json`، ومنطق اللغة في `i18n.py`.
- القيم المخزنة (أنواع الحسابات والقيود وأسماء المناطق) تبقى بالعربي في قاعدة البيانات وتُترجم عند العرض فقط.
- بعد أي تعديل في الواجهة شغّل:
```bash
.venv\Scripts\python tools\check_translations.py
```
  ويطبع أي نص عربي جديد ليس له ترجمة.

## بناء نسخة العملاء
```bash
.venv\Scripts\pyinstaller --noconfirm SmartAccounting.spec
```
يطلع `dist\NextGenAccounting.exe`. مجلد التسليم للعميل يحتوي فقط:
`NextGenAccounting.exe` + `تشغيل السيستم.vbs` + `إيقاف السيستم.vbs` + `الترقية من نسخة قديمة.vbs` + `طريقة التشغيل.txt`

- **لا ترسل** مجلد `instance` (بياناتك ومفتاح التشفير) ولا ملفات `.py`.
- ملفات `.vbs` محفوظة بترميز UTF-16 عمدًا — Windows Script Host لا يقرأ UTF-8، والنص العربي يفسد لو حُفظت بغيره.
- بيانات الشركة المطوّرة (الاسم، الموقع، الواتساب، الرخصة) في `PRODUCT` داخل `app.py`، وبيانات ملف الـ EXE في `version_info.txt`.

## النسخة الويب (سيرفر — نسخة مستقلة لكل عميل)
نفس الكود يشتغل كموقع على الإنترنت لما يتشغّل بـ `NEXTGEN_MODE=web` (راجع `config.py`):
HTTPS وكوكيز Secure، عنوان الزائر الحقيقي خلف Caddy، مفيش مستخدمين افتراضيين، وأي كلمة مرور يحددها المدير مؤقتة لازم تتغير أول دخول.

- سيرفر الإنتاج: `serve.py` (Waitress)، ونقطة WSGI: `wsgi.py`.
- إدارة نسخة عميل: `manage.py` (`init` / `reset-password` / `backup` / `info`).
- **الأسهل — Railway (بدون سيرفر):** من GitHub مباشرة، الدليل في **`deploy/RAILWAY.md`** (الإعدادات في `railway.json`).
- سيرفر VPS خاص (أرخص مع عملاء كتير): `Dockerfile` + `deploy/nextgen.sh` — الدليل في **`deploy/README.md`**.
- اختبار وضع الويب بالكامل (بيشغّل نسخة عميل مؤقتة لوحده):
```bash
.venv\Scripts\python test_web.py
```

## الوصول من خارج المكتب (نسخة الـ Desktop)
`تشغيل الجهاز الرئيسي للوصول من خارج البيت.bat` و `الاتصال من خارج البيت.bat` — التفاصيل في `دليل الربط من خارج البيت.txt`.
⚠️ الاتصال يتم عبر HTTP غير مشفّر — لا يُنصح به لبيانات مالية بدون VPN أو نفق مشفّر.
