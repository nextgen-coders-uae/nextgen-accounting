# رفع «نكست جين للمحاسبة» على الإنترنت — دليل خطوة بخطوة

## الفكرة باختصار

```
                    الإنترنت (HTTPS)
                          │
                ┌─────────▼──────────┐
                │  Caddy  (80/443)   │  ← شهادات HTTPS مجانية وتلقائية
                └───┬──────────┬─────┘
       client1.app…│          │client2.app…
          ┌────────▼───┐  ┌───▼────────┐
          │ حاوية عميل 1│  │ حاوية عميل 2│   ← كل عميل: برنامج لوحده
          │  + بياناته  │  │  + بياناته  │     + قاعدة بيانات لوحده
          └────────────┘  └────────────┘
                 سيرفر Linux واحد (VPS)
```

- **سيرفر واحد يشيل كذا عميل**، وكل عميل معزول تمامًا: قاعدة بيانات، مفتاح تشفير، نسخ احتياطية، ورابط خاص.
- أي عميل كبير تقدر تنقله لسيرفر لوحده في أي وقت بنفس الخطوات.
- كل حاجة بتتم بأمر واحد من الأداة `nextgen`.

---

## 1) اختيار شركة السيرفر

المطلوب: **VPS بنظام Ubuntu 24.04** — مواصفات البداية: **2 معالج / 4 جيجا رام / 40 جيجا SSD** (تكفي تقريبًا 20–30 عميل صغير).

| الشركة | لماذا | السعر التقريبي شهريًا* |
|---|---|---|
| **Hetzner Cloud** ⭐ (موصى به) | أفضل سعر مقابل الأداء، ثبات عالي، سيرفرات في ألمانيا وفنلندا | ~4–6 يورو (CX22) |
| **DigitalOcean** | الأسهل للمبتدئين، واجهة ممتازة وشرح كثير | ~12–24$ |
| **Contabo** | أرخص موارد (رام أكثر بنفس السعر)، الدعم أبطأ | ~5–7 يورو |
| **Hostinger VPS** | منتشر في المنطقة العربية ودعم بالعربي | ~7–10$ |
| **AWS / Microsoft Azure / Oracle Cloud** | لو العميل يشترط أن تبقى البيانات **داخل الإمارات** (مراكز بيانات في دبي/أبوظبي) | أغلى — حسب الخدمة |

\* الأسعار تتغير — راجعها وقت الحجز. أول سيرفر: ابدأ بـ **Hetzner CX22** أو **DigitalOcean 2GB**.

> عملاء حكوميين أو إدارات ميزانية غالبًا بيرفضوا الاستضافة الخارجية — لهم استخدم نسخة الـ Desktop (نفس البرنامج).

## 2) تجهيز الدومين (مرة واحدة)

الأسهل: سجل DNS واحد يخدم كل العملاء الجدد تلقائيًا.

من لوحة DNS عند الشركة اللي اشتريت منها `nextgen-coders.dev` أضف:

| النوع | الاسم | القيمة |
|---|---|---|
| `A` | `*.app` | عنوان IP بتاع السيرفر |

بعدها أي عميل جديد رابطه يكون مثلًا: `gulf-trading.app.nextgen-coders.dev` — بدون أي تعديل DNS تاني.

- لو بتستخدم **Cloudflare**: خلّي السحابة **رمادية (DNS only)** للسجل ده.
- لو العميل عاوز دومين شركته (مثل `accounts.clientco.com`): يضيف عنده سجل `A` يشاور على IP السيرفر، وتستخدم الدومين ده في أمر `nextgen new`.

## 3) تجهيز السيرفر (مرة واحدة)

### أ. مفتاح الدخول (من جهازك — PowerShell)
```powershell
ssh-keygen -t ed25519
```
اضغط Enter للكل. انسخ محتوى الملف `C:\Users\<اسمك>\.ssh\id_ed25519.pub` وحطه في خانة **SSH Key** وأنت بتعمل السيرفر عند الشركة.

### ب. الدخول على السيرفر
```powershell
ssh root@<IP-السيرفر>
```

### ج. تحديث + جدار حماية + Docker (انسخها كلها مرة واحدة)
```bash
apt update && apt -y upgrade
apt -y install ufw unattended-upgrades
ufw allow OpenSSH && ufw allow 80,443/tcp && ufw allow 443/udp && ufw --force enable
curl -fsSL https://get.docker.com | sh
```

---

## 4) رفع البرنامج

### من جهازك (PowerShell) — من المجلد اللي فيه ملف السيرفر:
```powershell
scp nextgen-accounting-server-v2.2.tar.gz root@<IP-السيرفر>:/root/
```
(أو استخدم برنامج **WinSCP** بالسحب والإفلات.)

### على السيرفر:
```bash
mkdir -p /opt/nextgen/app
tar -xzf /root/nextgen-accounting-server-v2.2.tar.gz -C /opt/nextgen/app
/opt/nextgen/app/deploy/nextgen.sh setup admin@nextgen-coders.dev
```
الإيميل بيستخدم لشهادات HTTPS المجانية (Let's Encrypt). بعد الأمر ده يبقى عندك أمر مختصر اسمه **`nextgen`**.

## 5) إضافة عميل جديد (كل عملية بيع)

```bash
nextgen new gulf-trading gulf-trading.app.nextgen-coders.dev --company "Gulf Trading LLC" --tz Asia/Dubai --lang en
```

| الجزء | المعنى |
|---|---|
| `gulf-trading` | اسم قصير للعميل (حروف إنجليزي صغيرة وأرقام و -) |
| الدومين | رابط العميل |
| `--company` | اسم شركة العميل (يظهر في البرنامج والتقارير) |
| `--tz` | توقيت العميل: `Africa/Cairo` مصر، `Asia/Dubai` الإمارات، `Asia/Riyadh` السعودية، `Asia/Kuwait` الكويت |
| `--lang` | لغة البداية: `ar` أو `en` (الإنجليزي بيحوّل أسماء الحسابات الافتراضية كمان) |

الأمر بيطبع **الرابط + اسم المستخدم + كلمة مرور مؤقتة** — ابعتهم للعميل.
أول ما يدخل، البرنامج **يجبره يغيّر كلمة المرور**. نفس الكلام لأي مستخدم يضيفه المدير.

## 6) الأوامر اليومية

| الأمر | الوظيفة |
|---|---|
| `nextgen list` | كل العملاء وحالتهم |
| `nextgen info <عميل>` | الشركة وعدد المستخدمين والقيود |
| `nextgen reset-password <عميل> [مستخدم]` | كلمة مرور مؤقتة جديدة (الافتراضي admin) |
| `nextgen logs <عميل>` | سجل التشغيل (للأعطال) |
| `nextgen stop / start / restart <عميل>` | إيقاف / تشغيل (مثلًا لو العميل ماجددش الاشتراك) |
| `nextgen backup all` | نسخة احتياطية فورية لكل العملاء |
| `nextgen remove <عميل>` | إزالة عميل — بياناته **بتتأرشف** في `/opt/nextgen/removed` ومش بتتمسح |

## 7) النسخ الاحتياطي

- **تلقائي كل يوم الساعة 2:30 صباحًا** لكل العملاء في `/opt/nextgen/backups/<عميل>/` — محتفظ بآخر 30 يوم.
- داخل البرنامج نفسه: نسخة شهرية + زر «نسخة احتياطية الآن» + تنزيل أي نسخة.

### ⚠️ مهم جدًا: نسخة خارج السيرفر
لو السيرفر نفسه وقع، النسخ اللي عليه تضيع معاه. فعّل واحد على الأقل:
1. **نسخ الشركة المستضيفة**: Hetzner Backups (+20% من سعر السيرفر) أو DigitalOcean Backups.
2. **rclone** لتخزين خارجي رخيص (Backblaze B2 أو Hetzner Storage Box):
   ```bash
   apt -y install rclone
   rclone config                                    # اعمل remote باسم مثلًا: b2
   echo 'RCLONE_REMOTE=b2:nextgen-backups' >> /opt/nextgen/nextgen.conf
   ```
   بعدها النسخ اليومية بتترفع هناك تلقائيًا.

### استرجاع عميل من نسخة
```bash
nextgen stop gulf-trading
cd /opt/nextgen/clients/gulf-trading/data/instance
rm -f accounting.db-wal accounting.db-shm
gunzip -c /opt/nextgen/backups/gulf-trading/gulf-trading-2026-10-01_023000.db.gz > accounting.db
chown 10001:10001 accounting.db
nextgen start gulf-trading
```

## 8) التحديثات (لما أبعتلك نسخة جديدة)

```powershell
scp nextgen-accounting-server-v2.3.tar.gz root@<IP-السيرفر>:/root/
```
```bash
tar -xzf /root/nextgen-accounting-server-v2.3.tar.gz -C /opt/nextgen/app
nextgen update
```
`update` بياخد نسخة احتياطية لكل عميل، وبعدين يشغّله بالنسخة الجديدة، وترقية قاعدة البيانات بتحصل لوحدها. العميل بيفصل ثواني بس. بعدها اتأكد بـ `nextgen list`.

## 9) قائمة الأمان

- [x] HTTPS إجباري وشهادات تلقائية (Caddy).
- [x] مفيش كلمات مرور افتراضية — كل كلمة مرور مؤقتة لازم تتغير أول دخول.
- [x] حماية من التخمين بعنوان الزائر الحقيقي + قفل مؤقت لاسم المستخدم.
- [x] كل عميل في حاوية منفصلة بمستخدم غير root وبحد أقصى للذاكرة.
- [ ] الدخول على السيرفر بمفتاح SSH فقط (خطوة 3)، وماتديش كلمة مرور root لحد.
- [ ] نسخة احتياطية خارج السيرفر (خطوة 7).
- [ ] احذف ملف `ADMIN-CREDENTIALS.txt` من مجلد العميل بعد ما تسلّمه البيانات (اختياري — الكلمة مؤقتة أصلًا).

## 10) مشاكل شائعة

| المشكلة | الحل |
|---|---|
| الرابط بيفتح بدون HTTPS أو شهادة غلط | اتأكد إن سجل DNS بيشاور على IP السيرفر (ممكن ياخد لحد ساعة)، وإن Cloudflare «DNS only»، وإن البورتات 80 و443 مفتوحة. بعدها: `docker logs nextgen-caddy` |
| صفحة «502 Bad Gateway» | العميل واقف: `nextgen logs <عميل>` ثم `nextgen restart <عميل>` |
| العميل نسي كلمة المرور | `nextgen reset-password <عميل> <المستخدم>` |
| عاوز أعرف المساحة | `df -h` و `du -sh /opt/nextgen/*` |
