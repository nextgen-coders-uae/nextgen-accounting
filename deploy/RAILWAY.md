# رفع «نكست جين للمحاسبة» على Railway — خطوة بخطوة (بدون أي سيرفر أو أوامر)

**الفكرة:** الكود على GitHub (مستودع خاص) ← Railway بيبني البرنامج ويشغّله ويديله رابط HTTPS.
**كل عميل = مشروع لوحده على Railway** ← برنامج لوحده + قاعدة بيانات لوحده (Volume) + رابط لوحده.
**التحديث لكل العملاء = رفع التعديل على GitHub** ← Railway بيحدّث كل المشاريع لوحده.

> أسماء الأزرار في Railway وGitHub ممكن تتغير شوية مع تحديثاتهم — الفكرة نفسها ثابتة.

---

## الجزء الأول: GitHub (مرة واحدة)

### 1) حساب GitHub
لو معندكش: ادخل **github.com** ← **Sign up** وأكمل التسجيل.

### 2) إنشاء مستودع خاص (فاضي)
1. من أعلى يمين الصفحة: علامة **+** ← **New repository**.
2. **Repository name:** `nextgen-accounting`
3. اختار **Private** ⚠️ (مهم جدًا — ده منتجك التجاري).
4. **ماتعلّمش** على «Add a README» ولا «.gitignore» ولا «license» — سيبه فاضي.
5. **Create repository** ← هيطلع لك رابط زي:
   `https://github.com/<اسم-حسابك>/nextgen-accounting.git`

### 3) رفع الكود من جهازك
الكود متجهّز ومحفوظ في git على جهازك بالفعل. افتح PowerShell داخل مجلد المشروع
`D:\NextGen company\NextGen-Coders-projects\SmartAccounting-main` ونفّذ (غيّر اسم الحساب):

```powershell
git remote add origin https://github.com/<اسم-حسابك>/nextgen-accounting.git
git push -u origin main
```
أول مرة هتفتح نافذة متصفح تطلب تسجيل الدخول في GitHub — وافق.
بعدها حدّث صفحة المستودع على GitHub هتلاقي الملفات (حوالي 75 ملف).

**بديل بالماوس:** برنامج **GitHub Desktop** ← File ← Add local repository ← اختار المجلد ← **Publish repository** (وسيب علامة «Keep this code private» ✔).

✅ اتأكد إن مفيش مجلد `instance` ولا `.venv` على GitHub (مستبعدين تلقائيًا).

---

## الجزء التاني: Railway (مرة واحدة)

1. ادخل **railway.com** ← **Login** ← **Login with GitHub** ← وافق.
2. اختار خطة **Hobby** (حوالي 5$ شهريًا وفيها رصيد استخدام) وضيف كارت الدفع.
   للشركات والفواتير الرسمية فيه خطة **Pro** (حوالي 20$).
3. اسمح لـ Railway يشوف المستودع الخاص: أول مرة تعمل «Deploy from GitHub» هيطلب **Configure GitHub App** ← اختار **Only select repositories** ← `nextgen-accounting` ← **Save**.

## الجزء التالت: إضافة عميل جديد (مع كل عملية بيع — حوالي 5 دقايق)

### الخطوة 1: مشروع جديد من GitHub
1. من لوحة Railway: **New Project** ← **Deploy from GitHub repo** ← `nextgen-accounting`.
2. غيّر اسم المشروع لاسم العميل (من إعدادات المشروع) — مثلًا `gulf-trading`.
3. Railway هيبدأ يبني تلقائيًا (بيستخدم `Dockerfile` و`railway.json` الموجودين في الكود).
   **أول تشغيل ده مؤقت — تجاهله** لحد ما تكمل الخطوات الجاية.

### الخطوة 2: الإعدادات (Variables)
اضغط على الخدمة (المربع) ← تبويب **Variables** ← **Raw Editor** ← الصق وعدّل القيم:

```
COMPANY_NAME=Gulf Trading LLC
DEFAULT_LANG=en
TZ=Asia/Dubai
ADMIN_PASSWORD=GulfStart2026
PORT=8000
RAILWAY_RUN_UID=0
```

| المتغير | معناه |
|---|---|
| `COMPANY_NAME` | اسم شركة العميل — يظهر في البرنامج والتقارير |
| `DEFAULT_LANG` | لغة البداية: `ar` أو `en` (الإنجليزي بيحوّل أسماء الحسابات الافتراضية كمان) |
| `TZ` | توقيت العميل: `Africa/Cairo` مصر — `Asia/Dubai` الإمارات — `Asia/Riyadh` السعودية — `Asia/Kuwait` الكويت |
| `ADMIN_PASSWORD` | كلمة مرور **مؤقتة** للمدير (8 حروف وأرقام على الأقل) — العميل بيتجبر يغيّرها أول دخول |
| `PORT` | سيبه `8000` |
| `RAILWAY_RUN_UID` | سيبه `0` — لازم عشان البرنامج يقدر يكتب في مساحة التخزين |

اضغط **Update Variables** (Railway هيعيد التشغيل).

### الخطوة 3: مساحة التخزين (Volume) ⚠️ أهم خطوة — من غيرها البيانات تضيع
1. في صفحة المشروع اضغط **Ctrl + K** (أو زر **+ Create** / كليك يمين على الخدمة) ← **Volume**.
2. اختار الخدمة بتاعة العميل.
3. **Mount path:** اكتب بالظبط:  `/data`
4. احفظ ← Railway هيعيد التشغيل.

### الخطوة 4: الرابط
1. الخدمة ← **Settings** ← **Networking** ← **Generate Domain**.
2. لو سألك عن البورت اكتب **8000**.
3. هيطلعلك رابط زي: `https://nextgen-accounting-production-xxxx.up.railway.app`

### الخطوة 5: التجربة
1. استنى لحد ما آخر Deployment يبقى **Active / Success** (أخضر).
2. افتح الرابط ← ادخل بـ:
   - اسم المستخدم: `admin`
   - كلمة المرور: قيمة `ADMIN_PASSWORD`
3. البرنامج هيطلب تغيير كلمة المرور ← غيّرها ← تفتح لوحة التحكم ✅
4. **مهم للأمان:** افتح **سجل العمليات (Audit Log)** ← آخر «تسجيل دخول» مكتوب جنبه عنوان IP.
   - لو هو نفس عنوانك الحقيقي (قارنه بموقع whatismyip.com) ← تمام.
   - لو طالع عنوان داخلي ثابت (بيبدأ بـ `10.` أو `100.` أو `172.`) ← ضيف متغير `PROXY_HOPS=2`، واعمل دخول تاني واتأكد.
     (ده بيضمن إن الحماية من تخمين كلمات المرور بتحظر المهاجم بس، مش كل العملاء.)
5. **امسح متغير `ADMIN_PASSWORD`** من Variables بعد ما العميل يدخل أول مرة (مش ضروري — مبيتطبقش تاني — بس أنضف).

### الخطوة 6: تسليم العميل
ابعت للعميل: **الرابط + admin + كلمة المرور المؤقتة**. أول ما يدخل هيغيّرها بنفسه.
المدير عند العميل يقدر يضيف باقي موظفينه من صفحة **المستخدمين** (وكل واحد بيغيّر كلمته أول دخول).

## دومين باسمك بدل `up.railway.app` (اختياري — شكل أحترف)
1. الخدمة ← **Settings** ← **Networking** ← **Custom Domain** ← اكتب مثلًا:
   `gulf-trading.app.nextgen-coders.dev`
2. Railway هيديك قيمة **CNAME** (مثل `xxxx.up.railway.app`).
3. في لوحة DNS بتاعة `nextgen-coders.dev` ضيف:

   | النوع | الاسم | القيمة |
   |---|---|---|
   | `CNAME` | `gulf-trading.app` | القيمة اللي Railway اداها لك |

4. استنى من دقايق لساعة ← Railway بيطلّع شهادة HTTPS لوحده ✅
   (لو بتستخدم Cloudflare خلّي السحابة رمادية «DNS only».)

## التحديثات (لما أعملك تعديل جديد)
من PowerShell داخل مجلد المشروع:
```powershell
git add -A
git commit -m "وصف التعديل"
git push
```
Railway بيحدّث **كل مشاريع العملاء** المربوطة بالمستودع تلقائيًا (والبيانات مابتتأثرش — ترقية قاعدة البيانات بتحصل لوحدها).
قبل تحديث كبير: خُد نسخة احتياطية (الجزء الجاي).

---

## النسخ الاحتياطي
1. **جوه البرنامج:** صفحة الإعدادات ← «نسخة احتياطية الآن» + نسخة تلقائية كل شهر + زر **تنزيل** لأي نسخة على جهازك.
2. **Railway Volume Backups:** اضغط على الـ Volume ← **Backups** ← فعّل جدول نسخ (يومي/أسبوعي) لو متاح في خطتك.
3. **عادة أسبوعية مقترحة:** نزّل نسخة من كل عميل على جهازك أو Google Drive.

## مشاكل وحلولها

| المشكلة | الحل |
|---|---|
| **العميل (المدير) نسي كلمة المرور** | في Variables ضيف `RESET_USERNAME=admin` و`RESET_PASSWORD=كلمة-مؤقتة` ← Railway يعيد التشغيل ← المدير يدخل بيها ويغيّرها. بتتطبق **مرة واحدة بس**؛ امسح المتغيرين بعدها. (أي موظف تاني: المدير عند العميل يعيد تعيين كلمته من صفحة المستخدمين.) |
| الـ Deployment فشل والـ Logs فيها `cannot write to the data folder` | اتأكد من `RAILWAY_RUN_UID=0` وإن الـ Volume متوصل على `/data` |
| الرابط بيقول Application failed to respond | اتأكد إن `PORT=8000` وإن بورت الرابط (Networking) = 8000 |
| نسيت `ADMIN_PASSWORD` قبل أول تشغيل | البرنامج بيولّد كلمة مؤقتة ويكتبها في **Deploy Logs** — دوّر على سطر `password:` |
| عاوز أوقف عميل مش بيدفع | من إعدادات الخدمة احذف الرابط أو أوقف الخدمة — البيانات فاضلة في الـ Volume |
| عاوز أعرف التكلفة | صفحة **Usage** في Railway — تقريبًا 1–3$ لكل عميل صغير شهريًا حسب الاستخدام |
